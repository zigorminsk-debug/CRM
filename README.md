# CRM — заявки на заправку картриджей и ремонт оргтехники

Клиент-серверная система приёма и обработки заявок для сервисной компании (Минск и Минская область).

* **Windows-клиент (`CRM-Windows.exe`)** — установленная форма заявки. Оператор заполняет обязательные
  реквизиты, адрес автоматически переводится в координаты, заявка уходит на сервер по публичному IP и порту.
* **Сервер (`server/`)** — принимает заявки, определяет **район** по адресу, находит **инженера, отвечающего
  за зону**, хранит **историю всех заявок** с поиском по контрагенту, УНП и расчётному счёту, ведёт
  **расписание доставок** и **перераспределяет зоны на время отпуска**.
* **Приложение инженера (Android, `android/`)** — получает заявки по зонам, строит **маршрут на день**
  с учётом срочности, открывает **Яндекс.Навигатор** по кнопке «Поехали», отмечает чекбоксами
  готовность **«на месте»** или **«забор в офис»**.
* **Веб-админка (`/admin`)** — зоны, инженеры, отпуска и замены, справочник работ, отчёты, журнал.
* **Мобильная PWA (`/m`)** — тот же функционал инженера без установки APK (можно добавить на главный экран).

```
  Windows-клиент (exe)                 Сервер (FastAPI + SQLite)                Приложение инженера
  ┌──────────────────┐   POST /api/requests   ┌────────────────────┐   маршрут   ┌──────────────────┐
  │ форма заявки     │ ─────────────────────► │ приём и валидация  │ ──────────► │ маршрут на день  │
  │ УНП / р/с / тел. │                        │ адрес → координаты │             │ «Поехали» →      │
  │ выпадающий список│ ◄───────────────────── │ район → инженер    │ ◄────────── │ Яндекс.Навигатор │
  │ работ, пояснение │   номер, статус, кто   │ история, зоны,     │  чекбоксы   │ на месте /       │
  └──────────────────┘                        │ отпуска, доставки  │  готовности │ забор в офис     │
                                              └────────────────────┘             └──────────────────┘
                                                        ▲
                                            веб-админка /admin (диспетчер)
```

## 1. Быстрый старт

### 1.1 Сервер (Python 3.10+)

```bash
cd server
python3 -m venv ../.venv && ../.venv/bin/pip install -r requirements.txt

# запуск (по умолчанию порт 8000, слушает все интерфейсы)
PORT=8000 python3 run.py
```

При первом запуске сервер сам создаёт базу, справочник работ, 31 зону (9 районов Минска + 22 района
области), локальный справочник адресов и двух пользователей:

| логин      | пароль       | роль                        |
|------------|--------------|-----------------------------|
| `admin`    | `admin123`   | администратор (веб-админка) |
| `engineer` | `engineer123`| инженер (мобильное приложение) |

**Сразу смените пароли** (админка → «Настройки» → «Пользователи») или задайте свой пароль администратора
при первом запуске: `CRM_ADMIN_PASSWORD='...' python3 run.py`.

Открыть в браузере: `http://<IP сервера>:8000/` — там ссылки на админку, мобильное приложение,
файлы приложений (`/downloads`) и API-документацию (`/docs`).

### 1.2 Windows-клиент

Готовый файл: **`downloads/CRM-Windows.exe`** (портативный, x64, ничего устанавливать не нужно).

1. Скопируйте exe на компьютер диспетчера и запустите.
2. Кнопка **«Настройки сервера»** → укажите `http://<публичный IP сервера>:8000` → «Проверить связь».
   Адрес сохраняется в `%APPDATA%\CRM-Kartridzh\client.ini`.
3. Заполните форму и нажмите **«Отправить заявку на сервер»**.

Пересобрать exe из исходников:

```bash
cd winclient
./build_windows.sh mingw        # MinGW-w64 (x86_64-w64-mingw32-g++)
./build_windows.sh zig          # либо кросс-компиляция через zig (pip install ziglang)
# результат: winclient/dist/CRM-Windows.exe
```

### 1.3 Приложение инженера

* **Без сборки:** откройте на телефоне `http://<IP сервера>:8000/m`, войдите логином инженера,
  в меню браузера выберите «Добавить на главный экран» — заработает как обычное приложение
  (уведомления, «Поехали», Яндекс.Навигатор).
* **APK:** исходники в `android/` (Kotlin, AndroidX, minSdk 24). Откройте папку в Android Studio и
  соберите `assembleDebug`, затем положите файл в `server/../downloads/CRM-Engineer.apk` под именем
  `CRM-Engineer.apk` — он появится на странице `/downloads`.

## 2. Как система обрабатывает заявку

1. **Приём.** Windows-клиент проверяет обязательные поля (УНП, р/с, телефон, контактное лицо, работа,
   адрес), нормализует телефон к `+375 XX XXX-XX-XX` и отправляет `POST /api/requests`.
2. **Адрес → координаты.** Сервер геокодирует адрес:
   Яндекс.Геокодер (если задан ключ) → Nominatim/OSM → **локальный справочник**
   (`server/app/data/minsk_streets.csv`, ~200 улиц Минска и населённых пунктов области, работает без интернета).
   Результат кэшируется в таблице `geo_cache`.
3. **Район → зона.** По названию района и координатам определяется зона обслуживания
   (9 районов Минска + 22 района Минской области).
4. **Зона → инженер.** Берётся основной закреплённый инженер зоны; если он в отпуске/на больничном —
   его **замена**; если замены нет — резервный инженер зоны, затем дежурный.
   Заявка получает статус «Назначена инженеру» и push-событие уходит в приложение инженера.
5. **Маршрут на день.** `GET /api/engineer/route` строит порядок объезда: сначала аварийные и срочные,
   затем остальные — по принципу «ближайший сосед»; считается время прибытия, пробег и общая загрузка,
   лишнее помечается как «не влезает в день».
6. **«Поехали».** Заявка переходит в «В работе», приложение открывает Яндекс.Навигатор
   (`yandexnavi://build_route_on_map?lat_to=…&lon_to=…`), при отсутствии навигатора — Яндекс.Карты.
7. **Чекбоксы готовности.**
   * «Готово на месте» → статус *Выполнено на месте*;
   * «Забор в офис» → статус *Забор в офис* и **автоматическая постановка доставки заказчику
     на следующий рабочий день** (выходные и праздники из таблицы `holidays` пропускаются).
8. **Доставка.** Если оборудование не готово, инженер (или диспетчер) переносит доставку на следующий
   рабочий день (`/api/engineer/delivery/{id}/postpone`, счётчик переносов и комментарий сохраняются).
   После выдачи — статус *Доставлено*.
9. **Отпуск и перераспределение.** В админке оформляется отсутствие (отпуск/больничный/отгул) с заменой:
   зоны основного инженера передаются замене на период отсутствия, а незавершённые заявки
   **переназначаются** на фактического ответственного. Удаление записи об отпуске возвращает зоны назад.
10. **История.** Все заявки, события и изменения хранятся в базе. Поиск: контрагент, УНП, р/с, телефон,
    номер, период, статус, инженер, зона, свободный текст; выгрузка в CSV (открывается в Excel).

## 3. Что где лежит

```
server/                 сервер: FastAPI + SQLite
  app/main.py           REST API, размещение статики, веб-админка и мобильная PWA
  app/db.py             схема и доступ к данным (заявки, зоны, закрепления, отпуска, доставки, история)
  app/validation.py     УНП (контрольная цифра), р/с (IBAN mod-97), телефон (+375)
  app/geocode.py        адрес → координаты: Яндекс → Nominatim → локальный справочник
  app/zones.py          зоны, закрепления, отпуска и замены, рабочие дни
  app/routing.py        маршрут на день, приоритеты, доставки
  app/requests_service.py  приём заявки, назначение инженера, статусы, поиск, отчёты, CSV
  app/seed.py           справочник работ, демо-инженеры, первичные зоны
  app/data/minsk_streets.csv  локальный справочник адресов (офлайн-геокодирование)
  app/static/admin/     веб-админка диспетчера
  app/static/mobile/    мобильное приложение инженера (PWA)
  tests/e2e_test.py     сквозной тест всей цепочки (39 проверок)
winclient/              Windows-клиент на C++/Win32 (WinHTTP), исходники + сборка exe
android/                приложение инженера для Android (Kotlin)
downloads/              готовые файлы для раздачи (exe, архивы исходников)
```

## 5. Требования и эксплуатация

* Сервер: Python 3.10+, ОС Linux/Windows. Порт по умолчанию 8000 (меняется переменной `PORT`).
  Для работы с интернета достаточно открыть этот порт; для HTTPS поставьте сервер за nginx
  с сертификатом Let's Encrypt.
* База: один файл SQLite (`server/data/crm.sqlite3`) — резервная копия делается копированием файла.
  Для нескольких участков с высокой нагрузкой можно перейти на PostgreSQL (слой доступа — в `app/db.py`).
* Интернет для геокодирования не обязателен: локальный справочник адресов покрывает Минск и районы области,
  а ключ Яндекс.Геокодера (админка → «Настройки») даёт точность до дома, когда связь есть.
* Роли: `admin` — всё, `operator` — заявки/зоны/отпуска без управления пользователями,
  `engineer` — только свои заявки и маршрут.
* Приём заявок (`POST /api/requests`) и геокодирование открыты без авторизации, чтобы Windows-клиент
  работал без входа. Если сервер смотрит в интернет, ограничьте доступ firewall'ом по IP офиса
  либо поставьте перед приложением nginx с basic-auth для пути `/api/requests`.

## 6. API (кратко)

| Метод | Путь | Назначение |
|-------|------|------------|
| POST | `/api/requests` | приём заявки из Windows-клиента |
| GET | `/api/requests?contractor=&unp=&bank_account=&phone=&q=&status=&date_from=&date_to=` | история заявок с поиском |
| GET | `/api/requests/export.csv` | выгрузка истории в CSV |
| GET | `/api/requests/{id}` | карточка заявки с историей событий и доставками |
| POST | `/api/requests/{id}/reassign` \| `/status` \| `/postpone` | переназначение, смена статуса, перенос |
| GET | `/api/geo/resolve?address=` | адрес → координаты, район, ответственный инженер |
| GET | `/api/engineer/route?day=` | маршрут инженера на день |
| POST | `/api/engineer/task/{id}/go` \| `/done` | «Поехали» и чекбоксы готовности |
| POST | `/api/engineer/delivery/{id}/done` \| `/postpone` | доставка заказчику и перенос |
| GET | `/api/engineer/feed?since=` | лента событий (long-poll) для push-уведомлений |
| GET/POST | `/api/admin/zones`, `/api/admin/assignments`, `/api/admin/absences`, `/api/admin/coverage` | зоны, закрепления, отпуска, покрытие |
| GET | `/api/admin/reports/summary` | отчёты (статусы, инженеры, районы, работы, загрузка) |

Полная документация — `http://<сервер>:8000/docs`.
