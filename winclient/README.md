# Windows-клиент приёма заявок (`CRM-Windows.exe`)

Портативный исполняемый файл для компьютера диспетчера: заполнение установленной формы заявки,
автоматический перевод адреса в координаты, отправка заявки на сервер по публичному IP и порту,
поиск по истории заявок и повторный заказ в один клик.

## Экран приложения

│ ┌───────────────────────────┐ │ Банк (необязательно)                                         │
│ │ ЗП-2026-00001 2026-09-27  │ │ Контактное лицо *                   Телефон * (+375 …)        │
│ │ ООО «Ромашка» [Выполнено] │ │ Работа * (выпадающий список)        Срочность                 │
│ │ …                         │ │ Адрес * [ … ] [Определить координаты]                         │

## Обязательные поля и проверки (те же, что на сервере)

| Поле | Проверка |
|------|----------|
| УНП | 9 цифр, контрольная цифра по алгоритму МНС РБ — ошибка подсвечивается сразу |
| Расчётный счёт | IBAN `BY…` 28 знаков с проверкой mod-97 либо 13-значный счёт |
| Телефон | любой ввод (`8 029…`, `+375 29…`, `+375 33…`) → `+375 XX XXX-XX-XX` |
| Контактное лицо | непустое |
| Работа | выбор из выпадающего списка (25 работ, загружается с сервера) |
| Адрес | геокодируется; поддерживаются Минск и Минский район (районы области — тоже) |
| Пояснение | свободный текст |

Пока форма не прошла проверку, заявка не уйдёт на сервер — вместо этого показывается список ошибок.

## Настройки

Кнопка **«Настройки сервера»**: адрес вида `http://<публичный IP или домен>:8000` с кнопкой
«Проверить связь». Файл настроек: `%APPDATA%\CRM-Kartridzh\client.ini`

```ini
[server]
url=http://10.20.30.40:8000
[update]
check_on_start=1        ; проверять обновления при запуске (флажок в диалоге настроек)
```

## Особенности работы

* Адрес геокодируется автоматически при выходе из поля и повторно перед отправкой, если менялся.
  В строке состояния видно район и инженера, которому уйдёт заявка.
* Кнопка **«Открыть в Яндекс.Картах»** — предпросмотр точки на карте.
* Раз в минуту клиент проверяет связь с сервером и показывает статус в нижней строке;
  при обрыве связи заявку можно отправить повторно — данные формы не теряются.
* После отправки поля очищаются, контрагент остаётся — удобно для повторных заявок.
* Слева — поиск по истории (контрагент, УНП, р/с, текст): выберите заявку и нажмите
  «Заполнить форму из выбранной заявки», чтобы создать повторную заявку тем же реквизитам.

## Обновление версии

Версия видна в заголовке окна и в статусной строке (кнопка «Обновление клиента» — проверка вручную).

1. Ветка собирается на GitHub Actions, релизу присваивается номер `1.0.<номер сборки>`,
   файлы кладутся в GitHub Release (там же `update.json` с версией и SHA-256).
2. При запуске клиент спрашивает сервер (`GET /api/updates`), сравнивает номер сборки со своим
   и предлагает обновление кнопкой «Обновить».
3. По согласию exe скачивается во временную папку, проверяется SHA-256, затем скрипт ждёт закрытия
   клиента, копирует новый файл поверх старого и запускает приложение заново.
   Настройки (`client.ini`) и данные не затрагиваются.
4. Сборка подписана постоянным ключом проекта (`signing/windows-signing.pfx`), поэтому Windows
   не помечает её как «неизвестную программу», а новая версия встаёт поверх установленной.

## Сборка

```bash
# exe с версией, ресурсами и подписью постоянным ключом
SIGN_PFX=../signing/windows-signing.pfx SIGN_PFX_PASS=crm-windows-key-2026 ./build_windows.sh zig

./build_windows.sh mingw   # x86_64-w64-mingw32-g++ (MinGW-w64)
./build_windows.sh zig     # кросс-компиляция через zig: pip install ziglang
./build_test.sh            # автотест клиентской логики (Linux, без GUI)
python3 ../tools/version.py   # версия, которая попадёт в сборку
```

Скрипт сборки сам берёт версию из `tools/version.py` (в CI это номер запуска Actions), собирает
ресурсы `src/main.rc` (версия файла в свойствах exe, манифест с обычными правами и DPI) и, если
задан `SIGN_PFX_PASS`, подписывает exe (osslsigncode в Linux/CI, signtool в Windows).
Результат: `dist/CRM-Windows.exe` и `dist/version.txt` (версия + SHA-256).

Файлы исходников:

| Файл | Назначение |
|------|------------|
| `src/main_win.cpp` | окно, форма, обработчики, диалог настроек |
| `src/api.cpp` | вызовы REST API сервера |
| `src/validate.cpp` | проверки УНП / р/с / телефона (порт серверной логики) |
| `src/json.h` | минимальный JSON-парсер/сериализатор (UTF-8, `\uXXXX`) |
| `src/http_win.cpp` | HTTP через WinHTTP: запросы API и скачивание обновления |
| `src/hash.cpp` | SHA-256 для проверки целостности скачанного обновления |
| `src/main.rc.in` / `src/main.manifest` | ресурсы: версия файла в свойствах exe, манифест, DPI |
| `src/http_posix.cpp` | HTTP через сокеты — для автотеста на Linux/CI |
| `src/main_test.cpp` | консольный автотест: валидация, геокод, отправка заявки, история, SHA-256, обновления |

Требования: Windows 10/11 x64 (на 7/8.1 нужен установленный Universal CRT), библиотеки
WinHTTP, COMCTL32, SHELL32 — входят в состав системы.
